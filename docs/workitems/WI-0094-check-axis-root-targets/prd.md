## 1. 개요

### 1.1 문제 (측정)

`checkDependencies` 의 `@axis-ds/*` 설치 확인 대상은 `declaredAxisPackages(pkg)`(앱 선언)뿐이었어요. 필수 · 권장 의존성은 WI-0081 부터 루트 선언을 인정하는데 `@axis-ds/*` 는 앱만 봐서, 루트에만 선언하고 설치하지 않은 앱(npm · pnpm 실설치에서 앱 해석 MODULE_NOT_FOUND)이 PASS 「3개 확인」이었어요(조사 단계 R1 측정, 이번 재측정 R1 · R6 · R8 · R10 · C1 에서도 같음). 이 경계의 근거는 문서상 「전이 표를 작게」라는 범위 최소화뿐이었어요(WI-0081 1.3 · 배치 6c).

### 1.2 결정 (2026-10-27 사용자 결정)

| # | 결정 |
|---|---|
| Q11 | `@axis-ds/*` 설치 확인 대상을 워크스페이스 루트 선언까지 넓혀요. 루트 출처 미설치는 「워크스페이스 루트에 선언돼 있지만 설치되지 않았습니다」로 구분하고, 기존 「워크스페이스 루트에 선언: …」 표시에도 넣어요. 종료 코드는 바뀌지 않아요(WARN) |
| Q19 | 루트 대상에 이름 필터를 두지 않고(앱 쪽과 같이 도구 패키지 포함), 앱 lockfile(P2)이 있어도 루트 선언을 무시하지 않아요(필수 · 권장 의존성과 같은 규칙). PnP 루트 전용은 WI-0091 Q1 규칙을 따라요 |

이 결정은 WI-0081 · 배치 6c 가 정한 경계(`@axis-ds/*` 는 앱 선언만)를 다시 정한 것이에요.

### 1.3 범위

- 포함: registry-core `dependencies-core.ts` `checkDependencies`(대상 · 문구 · 출처 표시)
- 제외: npm 워크스페이스 루트 선언의 설치 위치 문구(앱 디렉터리 `npm install` 은 루트 선언을 설치하지 않음, WI-0096), PnP 루트 전용 `@axis-ds/*` 의 별도 알림

## 2. 수용 기준

- **AC1**: 루트에만 선언한 `@axis-ds/*` 가 설치되지 않았으면 dependencies WARN 「워크스페이스 루트에 선언돼 있지만 설치되지 않았습니다: <이름> → <설치 명령>」, 끝에 「(워크스페이스 루트에 선언: …, <이름>)」. 종료 코드 불변
- **AC2**: 설치돼 있으면 PASS, 「N개 확인」 수만 늘고 출처 표시에 이름이 들어감
- **AC3**: 앱 · 루트 둘 다 선언이면 앱 출처(종전 문구). `@axis-ds/cli` 같은 도구 패키지도 대상. 앱 lockfile 이 있어도 루트 선언을 셈
- **AC4**: 음성 대조: 워크스페이스가 아닌 상위(N1) · `.git` 너머 루트(N2)의 선언은 대상이 아님. PnP 루트 전용은 대상이 아님
- **AC5**: CLI · MCP 같은 문구
